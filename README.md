# FUTURES BOARD

바이낸스 USDT 무기한 선물 실시간 스크리너. **서버 없이 브라우저에서만** 돌아가며
GitHub Pages 정적 호스팅으로 배포한다.

**추천대로 매매하면 손실이 난다.** 비용(왕복 0.14% + 펀딩)을 반영한 19,754건 시뮬레이션에서
매매당 평균 −0.199%였고, 반대로 매매해도 −0.081%였다. 이 사이트는 수익을 주장하지 않는다.

검증된 것은 **변동폭 추정치**와 **사건형 알림**이다(둘 다 '얼마나 움직이나'이지 '수익이 나나'가 아니다). 화면의 「예상 변동 4H」는 59일·39,522건 실측으로 보정했고
순위상관 ρ=0.62, 등급별 실측/예상 0.99~1.02배로 잘 맞는다. 반면 **방향(롱·숏) 예측력도,
스코어 순위의 우위도 확인되지 않았다.** 그래서 기본 정렬을 「변동 예상」으로 두고
화면과 자기검증 패널에 이 경계를 그대로 적는다.

가장 쓸모 있는 기능은 **알림**이다. 거래량 폭증·급변 같은 사건형 규칙이 뜬 뒤에는
그 종목의 평소 변동성보다 1.7~2.3배 크게 움직인다(t=2.4~3.4). 이 프로젝트에서
기준선을 이긴 유일한 부분이다.

**배포: https://purplusnow.github.io/futuresboard/**

최종 업데이트: 2026-08-11

## 왜 정적 페이지로 되는가

COIN BOARD(업비트)와 정반대 조건이다.

| | 업비트 | 바이낸스 fapi |
|---|---|---|
| 브라우저 직접 호출 | Origin 헤더 붙으면 즉시 429 → **서버 필요** | `access-control-allow-origin: *` → **서버 불필요** |
| rate limit 귀속 | 오리진(사이트) 단위 | **방문자 IP 단위** (2400 weight/분) |
| GitHub Actions | 스캔 주체 | 미국 IP라 451 차단 가능 → **안 씀** |

방문자 IP당 한도가 걸리므로 트래픽이 늘어도 예산이 분산된다. 정적 페이지에 유리한 구조다.
백테스트가 필요해지면 지역 차단이 없는 `data.binance.vision` 덤프를 쓴다.

## 실시간 경로 — WS 실측 결과

전부 WebSocket으로 받으려 했으나, fstream에서 **스트림 계열별로 수신이 갈렸다.**
노드·크롬 양쪽에서 6회 재현했고 같은 IP에서 REST는 정상이다. (측정: 2026-08-10, KR/KT)

```
✓ bookTicker · depth · trade
✗ kline_* · aggTrade · markPrice · miniTicker · ticker · forceOrder
✗ !ticker@arr   (현물 호스트에서도 0프레임)
```

원인은 확정하지 못했다. 그래서 원인에 기대지 않는 설계를 택했다.

- **실시간 가격** — `!bookTicker` 하나로 전 종목 최우선 호가 수신(초당 ~90건).
  중간가로 진행 중인 봉의 종가·고저를 갱신해 지표가 즉시 반응한다.
- **봉/펀딩/24h/OI** — REST 폴링. 합계 약 370 weight/분으로 한도의 15%.
- **kline WS** — 구독은 하되 8초 안에 프레임이 없으면 죽은 것으로 보고 REST로 전환.
  살아 있는 환경에서는 그만큼 REST를 아낀다. 현재 상태는 푸터에 표시된다.

## 스코어링

COIN BOARD의 설계를 이어받되 선물 팩터를 얹었다.

1. **절대 임계값을 쓰지 않는다.** 모든 팩터를 그 시점 유니버스 안에서 백분위로 환산한다.
   시장 전체가 오른 날 모두가 만점을 받는 왜곡을 막는다.
2. **양방향.** 롱·숏 점수를 각각 매기고 높은 쪽을 방향으로 채택한다.
   한쪽 곡선만 쓰면 숏 후보가 구조적으로 저평가된다.
3. **근거를 함께 낸다.** 점수만 보여주면 신뢰가 안 생긴다.
   그 종목이 유니버스 대비 가장 앞선 지표를 골라 실제 수치와 함께 태그로 붙인다.
4. **확신도는 기호로.** ◎ 상위 2% · ○ 상위 10% · △ 상위 25% · ※ 그 외/방향 불분명.
   점수가 좁은 구간에 몰리므로 절대 점수가 아니라 백분위로 매겨 자기보정되게 했다.

| 팩터 | 가중 | 선물 고유 |
|---|---|---|
| 거래량 급증 | 0.20 | |
| 추세 정렬 | 0.15 | |
| **OI 정렬** | 0.13 | ✓ OI가 가격과 같은 방향으로 늘면 신규 자금, 반대면 청산이 만든 움직임 |
| 1h / 4h 모멘텀 | 0.12 / 0.12 | |
| RSI 품질 | 0.11 | 60 부근 최적, 과열 급감점 |
| 변동성 대비 효율 | 0.09 | |
| **펀딩 여유** | 0.08 | ✓ 우리 방향이 이미 과밀하면 청산 연쇄의 표적 |

과열 캡: RSI 극단 ×0.75 · 24h 급등후 ×0.85 · 펀딩 과밀 ×0.85

## 자기검증

스크리너가 스스로를 검증하지 않으면 그냥 그럴듯한 화면일 뿐이다.
과거 구간을 되돌려 "그때 전광판이 뭐라고 했고, 그래서 어떻게 됐는지"를 집계한다.

```sh
python3 tools/fetch_history.py --days 60 --symbols 120   # 덤프 → .cache/ (약 2분)
node tools/replay.mjs --step 6                           # 리플레이 → docs/data/track.json
```

측정이 스스로를 속이지 않도록 세 가지를 강제한다.

1. **같은 코드로 재현한다.** 리플레이가 `docs/lib/*.js`를 그대로 로드한다.
   백테스트용 별도 구현을 두면 반드시 어긋나고, 어긋난 줄 모른 채 숫자를 믿게 된다.
2. **누수를 차단한다.** 시각 t의 판단에는 t까지의 봉만 쓴다. 24h 거래대금·등락률도
   t 기준으로 다시 계산하고(최종값을 쓰면 미래를 아는 것이다), 펀딩비는 t 이전에 확정된
   값만 쓴다. 진입가는 신호 봉의 종가가 아니라 **다음 봉 시가**다.
3. **베이스라인과 비교한다.** 하락장에서 숏 적중률 60%는 실력이 아니다. 같은 시각·같은
   방향으로 **같은 자격 풀**(노출 기준을 통과한 종목)에서 무작위로 골랐을 때와의 차이만 본다.

결과는 사이트 하단 패널에 그대로 노출된다. 유의성 판정(`track.verdict`)을 감추지 않는다.

### 측정 결과 (2026-06-12 ~ 08-09, 59일 · 119종목 · 신호 39,522건)

**방향은 맞히지 못한다.** 롱·숏 방향의 초과수익은 전 등급에서 0 또는 음수이고
통계적으로 유의하지 않다(◎ 4시간 −0.18%p, t=−0.42, 59일 중 25일만 양). 오히려 확신 등급이
높을수록 4시간 방향 성과가 나빴다 — 단기 모멘텀을 사서 되돌림을 맞는 전형적 패턴이다.

**움직임의 크기는 확실히 맞힌다.** 같은 시각 같은 자격 풀에서 무작위로 고른 종목 대비
|수익률| 배수가 등급 순서대로 정확히 줄어든다.

| 등급 | 15m | 1h | 4h | 4h 유의성 |
|---|---|---|---|---|
| ◎ | 2.06배 | 1.96배 | **1.91배** | t=7.2 ✓ |
| ○ | 1.51배 | 1.50배 | 1.41배 | t=6.9 ✓ |
| △ | 1.19배 | 1.19배 | 1.16배 | t=4.1 ✓ |
| ※ | 1.01배 | 1.02배 | **1.00배** | t=−0.0 (대조군) |
| *ATR 단순정렬* | — | — | *2.17배* | *t=−32.4 (우리 순위보다 우위)* |

「방향 불분명(※)」 등급이 정확히 1.00배라는 점이 중요하다. 모델이 "의견 없음"이라고 한 종목은
실제로도 평균과 구분되지 않는다 — 배수가 우연이 아니라는 내부 대조군 역할을 한다.

**단, 이 배수의 공로는 스코어 순위가 아니라 변동성(ATR)에 있다.** 같은 크기의 보드를
ATR로 단순 정렬하면 4.77% 움직여 스코어 보드(2.75%)보다 오히려 크다(t=−32.4).
스코어 순위가 자명한 기준선을 이긴다는 근거는 없다.

### 그래서 무엇을 파는가

세 번 측정해서 세 번 다 "순위에는 검증된 우위가 없다"가 나왔다. 남은 것은 이것뿐이다.

- **잘 보정된 변동폭 추정치** — ρ=0.62로 순서를 지키고 편향이 0.99~1.02배다. 이건 진짜다.
- **선물 맥락의 계기판** — 펀딩 극단, OI 급증, 거래량 배수, 근거 태그를 한 화면에서 본다.
- **자기검증 패널** — 무엇이 검증됐고 무엇이 안 됐는지 스스로 공개한다.

그래서 기본 정렬은 「변동 예상」(= 사실상 ATR 순)이고, 스코어는 참고용 탭으로 내렸다.
방향 배지는 남기되 눌러 두고 "검증되지 않았다"는 툴팁을 붙였다.
**예측기가 아니라 계기판이다.**

## 알림 — 이 프로젝트에서 유일하게 찾은 우위

계기판의 근본 약점은 "안 보면 소용없다"는 것이다. 그래서 조건이 걸리면 알린다.
탭이 열려 있는 동안만 동작한다(백그라운드 탭 포함). 서버가 없어 푸시는 불가능하고,
그 한계를 화면에 적어 둔다.

임계값을 감으로 정하면 알림은 소음이 된다. 그래서 규칙을 `docs/lib/alerts.js` 한 곳에
순수 함수로 두고 **리플레이가 같은 파일을 로드해** 규칙별 성과를 측정한다.

측정에서 규칙이 두 부류로 갈렸다. 판정 기준은 **사건 직전 그 종목의 변동성 대비**
실제로 더 움직였는가다. 현재 ATR과 비교하면 안 된다 — ATR(최근 70분)이 사건 봉을
이미 흡수해서 어떤 규칙도 1.0배로 나온다. 이 함정에 한 번 빠졌다.

| 규칙 | 성격 | 발동/일 | 직전 대비 | t | 판정 |
|---|---|---|---|---|---|
| 거래량 폭증 (강, 8배+) | 사건 | 7 | **2.29배** | 2.6 | ✅ 새 정보 |
| 급변 (강, ATR 4배+) | 사건 | 7 | **1.96배** | 2.4 | ✅ |
| 거래량 동반 돌파 (강) | 사건 | 23 | **1.71배** | 3.4 | ✅ |
| 펀딩 극단 | 상태 | 89 | 0.99배 | −0.3 | ❌ 만성 고변동 종목일 뿐 |
| 스퀴즈 임박 | 상태 | 1 | 1.01배 | 0.0 | ❌ |

**사건형 규칙은 그 종목의 평소보다 1.7~2.3배 크게 움직인다.** 스코어 순위·방향 예측이
모두 기준선에 진 뒤 처음 확인된 실질적 우위다.

상태형(펀딩·스퀴즈)은 기본으로 꺼 두었다. 발동 후 변동폭이 커 보이지만(펀딩 극단 6.07%)
그건 원래 변동성이 큰 종목을 다시 지목한 것뿐이라 알릴 가치가 없다 — 보드의 탭이 맞는 자리다.

기본값도 측정에서 나왔다: **사건형 3종 · 강도 2만**. 강도 1까지 켜면 하루 200회로
소음이 되고, 강도를 올릴수록 우위도 커진다(거래량 폭증 1.62배 → 강 2.29배).
같은 종목·규칙은 30분 쿨다운, 브라우저 알림은 분당 3건으로 캡한다.

## 매매 검증 — 실제로 돈이 되는가

앞의 모든 측정은 **총수익**이었다. 선물은 왕복 수수료·슬리피지에 펀딩까지 더하면
0.15% 안팎이 나가는데 측정된 방향 우위는 그보다 작았다. 비용을 빼지 않은 수익률은
검증이 아니라 착시라서, 비용을 넣은 원장을 따로 만들었다.

```sh
node tools/paper.mjs --from 2026-08-10 --to 2026-08-10   # → docs/data/ledger.json
```

비용 가정: 테이커 0.05% × 2 + 슬리피지 0.02% × 2 = 왕복 **0.14%**, 여기에 보유 중
발생한 펀딩을 실비로 더한다. 진입은 신호 다음 봉 시가, 청산은 4시간 뒤 종가다.

### 결과 (59일 · 19,754건)

| 전략 | 매매수 | 평균 총수익 | **평균 순수익** | 승률 |
|---|---|---|---|---|
| 모델 방향 (스코어 상위 14) | 19,754 | −0.073% | **−0.199%** | 43.3% |
| 모델 반대매매 | 19,754 | +0.073% | **−0.081%** | 48.5% |
| ◎ 등급만 | 1,530 | −0.158% | **−0.236%** | 42.9% |
| 사건형 알림 (강) | 886 | −0.517% | **−0.667%** | 40.1% |
| 대조군 (자격 풀 전부 롱) | 63,383 | +0.010% | **−0.100%** | 43.6% |

**전부 손실이고, 뒤집어도 손실이다.** 대조군이 −0.100%인 것은 그냥 비용을 낸 값이다.

특히 **사건형 알림이 가장 나쁘다**(−0.667%). 알림은 "무언가 벌어진다"를 맞히지만
그 방향으로 따라 들어가면 되돌림을 맞는다. **변동폭 예측력과 매매 수익성은 별개**라는
것이 숫자로 확인됐다. 알림은 "볼 만한 종목"을 고르는 도구지 진입 신호가 아니다.

### 전진 검증

백테스트는 "과거에 맞춰 조정했을 수 있다"는 의심을 구조적으로 벗지 못한다. 그래서
모델을 **2026-08-11에 동결**하고, 그 이후 생긴 데이터만 따로 쌓는다. 원장에서 두 구간을
절대 합치지 않는다.

매일 03:30 UTC에 `.github/workflows/forward-test.yml` 이 전날 덤프를 받아 하루치를
채우고 커밋한다. 각 기록에 모델 커밋 SHA가 남아, 모델이 데이터보다 먼저였음을
제3자가 확인할 수 있다.

Actions에서 도는 이유는 실측 때문이다 — 러너(San Jose, US)는 fapi가 전 엔드포인트
**451**이고 `data.binance.vision` 덤프는 **200**이다. 그래서 종목 목록을
`docs/data/universe.txt` 에 동결하고 덤프만으로 돌린다. 목록 고정은 생존 편향도 없앤다.

## 실행

```sh
cd docs && python3 -m http.server 8912
# http://localhost:8912
```

빌드 단계가 없다. `docs/`가 GitHub Pages 소스이므로 main에 push하면 그대로 반영된다.

커스텀 도메인을 붙이려면 `docs/CNAME`에 호스트명을 넣고 DNS에 CNAME 레코드
(`futures.koreanblog.xyz` → `purplusnow.github.io`)를 추가하면 된다. 지금은 기본 URL을 쓴다.

## 알려진 제약

- **미국 등 일부 지역 방문자는 화면이 뜨지 않는다.** 브라우저가 바이낸스를 직접 호출하는
  구조라 방문자 IP가 차단되면 451이 뜬다. 이 경우 안내 문구를 표시한다.
- **자동 매매는 넣지 않는다.** 주문은 시크릿 키 서명이 필요한데 브라우저에 키를 두는 것은
  안전하지 않다. 이 프로젝트의 경계는 스크리닝·신호까지다.
- OI는 WS 스트림이 없어 상위 40종목만 60초 주기로 폴링한다. 나머지는 해당 팩터가 중립 처리된다.
